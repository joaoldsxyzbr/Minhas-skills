# Product Design

Use for product discovery, UX research, interaction design, flow audits, or visual implementation based on an existing reference. Do not turn a straightforward code edit into a redesign.

## Understand the outcome

- Identify the user, the task they need to complete, and what success looks like.
- Inspect available screens, flows, analytics supplied by the user, support evidence, and product constraints before asking for information already present.
- Distinguish observed evidence from assumptions. Avoid inventing user research or claiming that a design is validated without a test.
- Ask only for decisions that would materially change the design; otherwise state sensible assumptions and continue.

## Explore options

For a new or significantly changed flow, describe the key alternatives, their tradeoffs, and a recommendation. Use a sketch, flow, or prototype when that will make the choices easier to evaluate. Keep exploration focused on the user's task, not visual novelty.

## Audit an existing experience

Review a complete task flow when possible. Check:

- Clear labels, information hierarchy, and next steps.
- Error prevention, recovery, and confirmation for consequential actions.
- Keyboard access, focus order, contrast, responsive behavior, and accessible names.
- Empty, loading, error, permission, and success states.
- Consistency with the existing product and user expectations.

Report findings with the affected screen or step, user impact, severity, and a practical fix. Separate usability problems from personal preference.

## Implement and validate

Preserve existing architecture and working behavior. Use supplied screenshots, URLs, or design files as the reference. Validate at relevant viewport sizes and inspect the rendered result when tools allow. If visual verification is unavailable, state that limitation plainly.

Do not claim an interface is usable or accessible solely because the source code looks correct.
