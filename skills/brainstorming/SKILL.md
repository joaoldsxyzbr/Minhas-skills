# Brainstorming

Apply the [shared workflow rules](../using-minhas-skills/references/workflow-rules.md); read once and reuse for this task.

## Establish what is missing

Inspect the user's context and relevant project material first. Separate stated requirements, observed facts and assumptions. If the result is already specified and implementation authorized, proceed without a discovery interview.

Product experience and UX direction belong to the bundled [product-design-ideation](../product-design-ideation/SKILL.md); use that discovery flow instead of repeating this one.

## Explore only consequential decisions

Identify the goal, users, success criteria, constraints and non-goals. Ask one focused question only when the missing answer changes the result materially. Do useful read-only investigation without asking permission for every lookup.

When there are meaningful alternatives, present only those needed to make the decision, with evidence, cost and tradeoffs; recommend the best-supported direction. Do not manufacture options or impose a fixed count for a small decision. A diagram or prototype may help, but must not require a companion server or external skill.

## Deliver and hand off

Summarize the chosen direction, assumptions, constraints, acceptance criteria and unresolved risks. For substantial work, write a short design in the project's documentation convention when useful. A small task can stay in the conversation.

If the user requested ideas or a plan only, stop at that deliverable. If implementation is already authorized, proceed with routine decisions within scope. Clarify only a material unresolved choice. Use [writing-plans](../writing-plans/SKILL.md) for a substantial implementation, not as a mandatory gate for every idea.
