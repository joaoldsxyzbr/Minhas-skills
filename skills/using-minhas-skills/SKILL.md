# Using Minhas Skills

Use this router when a task clearly matches a skill in this collection. For a simple question or small direct edit, answer or act directly without adding process.

## Choose the workflow

- New feature or unclear product idea: brainstorming; for a new product experience, use product-design-ideation.
- Agreed requirements that need an implementation plan: writing-plans; carrying out an agreed plan: executing-plans.
- Bug or failure with an unknown root cause: systematic-debugging first. Once investigation identifies the cause, use test-driven-development before changing code. If the root cause is already established, use test-driven-development directly.
- Before reporting technical work as complete: verification-before-completion.
- Product UX research or design direction: product-design-ideation; audit an existing flow: product-design-audit; implement a reference and validate rendering: product-design-implementation-qa.
- Cloudflare platform work: cloudflare-platform; D1 schemas, migrations, bindings, or queries: cloudflare-d1. For Cloudflare implementation and troubleshooting, use the relevant technical skill before broad research.
- GitHub repositories, branches, commits, or pull requests: github-workflows; isolate substantial work: using-git-worktrees; review a diff: code-review; prepare completed work for handoff or integration: finishing-branch. For GitHub implementation and troubleshooting, use the relevant workflow before broad research.
- Creating or auditing a skill: skill-authoring-audit.
- Use deep-research for broad, cross-domain, comparative, or evidence-heavy questions. For a question contained within a specific technical domain, start with that domain's skill and add deep-research only when broader independent evidence is needed.

Use only the relevant workflow. Do not invoke every skill on every turn. Treat an explicit request to implement, apply, or execute a scoped change as authorization for the necessary routine steps and decisions within that scope; do not ask for approval again at each phase. Ask only when a missing decision would materially change the result or when a consequential action was not authorized.
